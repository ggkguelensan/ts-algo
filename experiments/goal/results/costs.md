## Temporal break-even illustration

Combines separate build/query reports from the same runtime and fixture. A 16-window query batch is normalized per window; estimated break-even is build cost divided by per-window saving over a prepared sorted linear scan. Input normalization/fixture generation is excluded for every variant. This is a cost-model estimate, not an observed latency threshold; use local distributions.

| Runtime | 100000-event shape | Current estimated queries | Temporal-only estimated queries |
|---|---|---:|---:|
| node | points | 55 | 45 |
| node | short | 64 | 48 |
| node | long | 72 | 188 |
| node | nested | 76 | 1688 |
| node | mixed | 52 | 40 |
| bun | points | 122 | 125 |
| bun | short | 140 | 134 |
| bun | long | no saving | no saving |
| bun | nested | no saving | no saving |
| bun | mixed | 116 | 120 |

For point-only inputs the binary-search prefix baseline is even cheaper than a general interval index; for many long/nested results a native prefix scan can win. Those baselines and full rebuild workloads are in the other tables. No single break-even number applies to all timelines.
