## Investigation of measured overhead

Initial public samples were retained in migration-structure-initial-node/bun.json. They exposed a costly generic reference-only collection loop and redundant membership lookup in causesOf. A general Array.from replacement was rejected after Node did not improve (migration-structure-native-from-node/bun.json). Final collect uses native slice only for internal owned dense-array bindings with an unchanged iterator. Arbitrary from/subset inputs retain iteration/holes semantics; replaced iterators fall back to iteration. Filtered/projected/limited loops keep their callback and early-close contracts. causesOf uses one get with an undefined check, because every valid node owns a causes array. Full root tests pass after both changes.

| Runtime | 20000-node cached order | Initial public ms | Final public ms | Legacy array-copy ms | Prototype recompute ms |

| node | topological refs | 0.174615 | 0.039631 | 0.026402 | 0.878005 |
| bun | topological refs | 0.118968 | 0.005945 | 0.010184 | 0.896693 |

Cached order retains one extra Ref array from Kahn validation and returns a bound Source; result arrays are only created by the consumer. Comparing that to prototype/Graphology recomputation illustrates a policy difference, not a universally faster topological algorithm. Original graph-source order remains input order. Tree traversal uses two depth stacks with borrowed sibling groups, avoiding wide-group copies before early yield. Prepared tasks retain a measured public overhead versus native/prototype in some cases: Source collection resolves each entity through the live binding, whereas the scenario prototype performs its business filter directly over materialized Map entries. This exceeds the relative investigation threshold in some rows and is accepted for the explicit binding/early-stop contract; no fastest-query claim is made. Native indexed loops remain a cheaper alternative. Full/cold scenario and sample ranges are shown above.
