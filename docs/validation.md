# Проверка контрактов

Алгоритмы могут опираться на явно сформулированные ограничения источника.
Библиотека предоставляет проверку плотности массива отдельно от сортировки,
чтобы один и тот же источник не проверялся перед каждой операцией.

## Плотный массив

Плотность означает: для каждого целого индекса от 0 до length - 1 массив
имеет собственное свойство. Пустой массив плотный. Значение undefined не
является дыркой; унаследованное значение по индексу не заменяет собственное.
TypedArray и похожие на массив объекты не являются обычными массивами.

```ts
import { isDenseArray } from "ts-algo";

isDenseArray([]);          // true
isDenseArray([undefined]); // true
isDenseArray(new Array(1)); // false
isDenseArray([1, , 3]);    // false
```

isDenseArray использует Array.isArray и Object.hasOwn. Время O(n), дополнительная
память O(1), остановка при первой дырке. Элементы не читаются и не копируются;
обычный frozen-массив тоже поддерживается. Проверка формы не проверяет типы
элементов. Предикат сужает unknown до unknown[].

## Zod Mini

```ts
import * as z from "zod/mini";
import { denseArray } from "ts-algo/zod";

const schema = denseArray(z.optional(z.number()));
const result = schema.safeParse([1, undefined, 3]);
// result.data при успехе: (number | undefined)[]

const nonEmpty = denseArray(z.number()).check(z.minLength(1));
const lengths = denseArray(z.pipe(z.string(), z.transform(value => value.length)));
// lengths.parse(["a", "abc"]): [1, 3]
```

Сначала проверяем форму исходного значения, затем передаём массив в z.array
со схемой элемента. При дырке схема элемента вообще не запускается. Ошибки
элементов сохраняют путь с индексом; ошибка плотности относится ко всему
массиву. Асинхронные схемы элементов требуют parseAsync/safeParseAsync.

Обычная z.array(z.optional(...)) может принять дырку как undefined и создать
плотный результат. Поэтому `.check` после такой схемы уже не удостоверяет
плотность исходного массива. Наш валидатор отклоняет дырки, не исправляет их.
Нельзя заменять проверку индексным `.every` или `.forEach`: они пропускают
отсутствующие индексы.

Zod создаёт новый массив; обработка сущностей зависит от схемы элемента.
Например, z.object парсит объект в новый объект. Если нужно сохранить
идентичность уже типизированных сущностей, используйте isDenseArray для формы.
Схему z.custom можно использовать для проверки элемента с сохранением ссылки,
но её предикат должен действительно проверять обещанный тип.

Zod — опциональная peer dependency: нужен только при импорте ts-algo/zod.
Корневой entry не импортирует этот модуль. Не создавайте схемы внутри
компараторов и не повторяйте парсинг при каждом сравнении.

## Что проверка не обещает

- Последующее delete или изменение length может нарушить плотность.
- Проверка собственных индексов не гарантирует отсутствие getters/Proxy;
  они должны соблюдать контракт отсутствия побочных изменений при работе.
- Плотность по контракту JS не гарантирует внутренний PACKED elements kind
  V8 и не превращает существующий массив в более быстрый автоматически.
  [Описание представлений массивов V8](https://v8.dev/blog/elements-kinds).
- Конечность произвольного Iterable и согласованность компаратора нельзя
  доказать таким валидатором; они остаются отдельными требованиями алгоритма.

Существующие проверки конструкторов индексов остаются: временные/пространственные
значения конечны, границы согласованы, связи не содержат запрещённых циклов.
Не дублируем стандартные проверки Zod собственной обёрткой без нового
контракта: например, минимальную длину задаёт z.minLength, число — z.number.
