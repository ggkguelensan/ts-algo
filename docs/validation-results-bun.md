# Проверка плотных массивов

Среда: Bun 1.3.14 / JavaScriptCore, Zod 4.6.5, Apple M5, darwin/arm64.

Исходные данные: [validation-results-bun.json](validation-results-bun.json). 3 прогрева, 7 образцов; порядок вариантов чередуется, GC перед образцом вне замера. Время одного вызова: медиана / min / max в миллисекундах.

| n | Операция | Медиана | min | max |
|---:|---|---:|---:|---:|
| 100 | shapeOnly | 0.0014 | 0.0013 | 0.0015 |
| 100 | elementsOnly | 0.0008 | 0.0007 | 0.0008 |
| 100 | shapeAndElements | 0.0022 | 0.0022 | 0.0024 |
| 10000 | shapeOnly | 0.4784 | 0.4235 | 0.4934 |
| 10000 | elementsOnly | 0.0732 | 0.0713 | 0.0776 |
| 10000 | shapeAndElements | 0.4984 | 0.4704 | 0.5106 |
| 100000 | shapeOnly | 5.2709 | 5.1302 | 5.4537 |
| 100000 | elementsOnly | 0.7514 | 0.7182 | 0.7695 |
| 100000 | shapeAndElements | 6.1199 | 5.8819 | 6.2550 |

shapeOnly — isDenseArray: только наличие собственных индексов, без чтения значений и копирования. elementsOnly — нативная для Zod схема z.array(z.optional(z.number())): проверка элементов и создание нового массива; дырки не отклоняет. shapeAndElements — denseArray той же схемы элементов: оба контракта и новый массив. Это стоимость разных проверок, а не сравнение равнозначных алгоритмов.

Схемы создаются до замера. Вход плотный, с явным undefined на каждом десятом месте. На малых входах несколько вызовов в образце; время делится на их количество. Пиковая память и браузеры не измерялись; автоматический GC внутри образца возможен. Проверка формы не гарантирует конкретный elements kind JS-движка.
