# Сортировка ссылок

```ts
import { sortedReferences } from "ts-algo";

const keys = sortedReferences(map, (entity, key) => entity.age, compare);
const values = sortedReferences(set, entity => entity.age, compare);
```

Источник — ReadonlyMap, ReadonlySet, плотный массив или конечный Iterable.
Map передаёт селектору сущность и ключ, возвращая ключи. Остальные источники
передают и возвращают элементы. Итераторы полностью потребляются один раз.
Дерево и хронология реализуют ReadonlyMap; очереди и списки — Iterable.

Результат — новый массив исходных ссылок. Сущности и источник не изменяются,
объектные ссылки сохраняют идентичность. Объекты не замораживаются библиотекой.
При n > 1 селектор вызывается один раз на каждое вхождение. Пустой и
одноэлементный источники не вызывают ни селектор, ни компаратор.

Равные значения сохраняют порядок обхода источника. Компаратор возвращает
отрицательное число, ноль или положительное число, задаёт согласованный порядок
и не возвращает NaN. Колбэки не должны изменять источник или порядок сравнения.

## Внешнее хранилище

Массив ссылок тоже поддерживается: селектор может получать сущность из отдельного
хранилища. В этом случае вызывающий код отвечает за отсутствующие сущности.
Для Map это разрешение уже выполняет библиотека: селектор получает значение
непосредственно при обходе записей, без Map.get внутри компаратора.

## Стоимость

Значения и исходные индексы кешируются в параллельных массивах; индексы сортируются
нативным Array.sort, после чего собирается результат. Объекты `{ ref, value }`
на каждый элемент не создаются. Сортировочный алгоритм выбирает JS-движок.

Для массива при n > 1 выделяются массивы значений, индексов и результата.
Для Map, Set и других Iterable дополнительно материализуются ссылки для
индексного доступа. Это O(n) вспомогательной памяти нашего кода; внутренние
буферы движка и выделения внутри селектора учитываются отдельно.

Обычный `references.slice().sort((a, b) => compare(getValue(a), getValue(b)))`
выделяет меньше вспомогательных массивов, но повторяет получение значений во
время сравнения. Кеширование особенно полезно для дорогих селекторов; оно не
обещает ускорение любой сортировки. [Замеры](benchmark-results.md),
[перегрузки коллекций](collections-results.md), [размер импорта](bundle-results.md).

Референсный Quicksort находится в [references](../references/README.md),
используется тестами и бенчмарками и не является публичным API библиотеки.
