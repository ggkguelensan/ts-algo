# Дерево и хронология

Сущности не изменяются и не копируются. Оба вида реализуют `ReadonlyMap`, поэтому
`sorted(view, entity => entity.rank, compare)` возвращает плоский массив
ключей. Итерация Map даёт пары, `keys()` — ключи. Структурные массивы readonly
по контракту; runtime не замораживает их. Селекторы не должны менять источник.

## Дерево

Родитель — метаданные иерархии, не обязательное свойство сущности. Селектор
parent(entity, key) может читать саму сущность или внешнюю Map по ключу:

```ts
import { tree } from "ts-algo";

const storage = new Map([
  ["root", { title: "Каталог" }],
  ["child", { title: "Телефоны" }],
]);
const parents = new Map([["child", "root"]]);
const hierarchy = tree(storage, { parent: (_entity, key) => parents.get(key) });
hierarchy.children("root"); // ["child"]
```

Отсутствующая запись в parents означает корень. Селектор вызывается один раз
для каждого узла; затем операции читают собственные Map связей дерева.
Изменение внешней parents не меняет уже построенную иерархию. Одни сущности
могут участвовать в нескольких деревьях с разными связями.

Если сущность действительно имеет parentId, допустим прежний вариант:

```ts
const hierarchy = tree(storage, { parent: item => item.parentId });
hierarchy.roots;
hierarchy.children(parentId);
hierarchy.parent(itemId);
hierarchy.nextSibling(itemId);
hierarchy.previousSibling(itemId);
[...hierarchy.subtree(itemId)]; // preorder, включая узел
[...hierarchy.ancestors(itemId)]; // ближайший родитель первым
const ordered = hierarchy.sortBy(item => item.title, (a, b) => a.localeCompare(b));
```

Это лес: несколько корней допустимы. `null`/`undefined` в селекторе родителя
обозначают корень, поэтому ключи должны быть non-nullish. Отсутствующий родитель,
цикл и неизвестный узел — RangeError. На границе группы сосед возвращает undefined.
Переходы `nextSibling`/`previousSibling` остаются среди детей одного родителя;
корни тоже одна группа. Это не переход к следующему узлу обхода preorder.

`sortBy` устойчиво сортирует корни и каждую группу детей, возвращая новый вид;
отношения и сущности сохраняются. Группы из одного узла не вызывают селектор,
остальные вызывают его один раз на узел. `keys()` выполняет preorder в текущем
порядке соседей. Обходы итеративны; цепочка глубиной 20 000 проверяется тестом.

Дерево снимает состав Map и ссылки на сущности при создании. Замена записи
исходного Map не заменяет сущность в дереве; изменение сущности не обновляет
связи. Для новой структуры требуется перестроение. Вложенные `children` требуют
адаптера; это бизнес-иерархия, не сбалансированное дерево поиска.

Явный context для геттеров всех структур и прямой ввод метаданных входят
в [целевой интерфейс](design.md#сущности-и-метаданные-структуры). Сейчас
parent дерева принимает entity/key; дополнительное хранилище захватывается
замыканием, как в примере выше.

При обычной средней стоимости Map-операций построение/полный обход O(n),
предки O(h), поддерево O(k), переход к соседу O(1). Последнее оплачивается
дополнительным Map позиций O(n). Сортировка — сумма сортировок групп плюс O(n)
подготовка. Сущности не оборачиваются в узлы и не получают поля children.

## Хронология: ссылки, время и причинность

Хронология привязывает ссылки к времени и причинным связям. Свойства `ownerId`,
статус и категория принадлежат сущности; специальных полей/индексов владельца нет.
Результаты запросов — исходные ссылки в хронологическом порядке, устойчивом при
равных началах. Хронология не добавляет полей самим сущностям.

```ts
const history = timeline(storage, {
  time: event => event.at, // либо { start, end }
  causes: event => event.causedBy,
});
history.between(start, end, event => event.ownerId === ownerId);
history.overlapping(start, end, event => event.status === "active");
history.filter(event => event.ownerId === ownerId);
history.causesOf(eventId);
history.effectsOf(eventId);
history.ancestors(eventId);
history.descendants(eventId);
history.causalOrder();
history.timeOf(eventId);
```

Если сущности имеют стандартные `{ at }` или `{ start, end }` и необязательные
`causes`/`effects`, достаточно `timeline(storage)`. Это также работает с Set,
массивом и конечным Iterable сущностей: ссылкой становится сама сущность.
При явных options нужен `time`; причинные селекторы необязательны. Без них
случайно одноимённые поля сущности не интерпретируются как связи.

События и временные данные могут находиться в разных источниках:

```ts
type Event = Readonly<{ ownerId: string; title: string }>;
const entities = new Map<string, Event>();
const times = new Map<string, number | { start: number; end: number }>();
const links = new Map<string, readonly string[]>();
const context = { entities, times, links };
const history = timeline(eventIds, {
  context,
  get: (id, ctx) => {
    const event = ctx.entities.get(id);
    if (!event) throw new Error(`Missing event: ${id}`);
    return event;
  },
  time: (_event, id, ctx) => {
    const time = ctx.times.get(id);
    if (time === undefined) throw new Error(`Missing time: ${id}`);
    return time;
  },
  causes: (_event, id, ctx) => ctx.links.get(id),
});
history.between(0, 100, (event, _id, ctx) => event.ownerId === ownerId);
history.context === context; // true
```

Для Map сущности получаются непосредственно из Map; тот же `context` можно
передать селекторам времени и связей. Для Iterable ссылок `get` разрешает сущность;
без get элементы сами являются сущностями. Ссылки должны быть уникальны.
Контекст и сущности сохраняют идентичность. Все вызовы синхронны; асинхронный
источник нужно предварительно загрузить или дать синхронный кеш.

Состав, время и причинность — статический снимок. `time` и переданные селекторы
связей вызываются один раз на событие при построении. Сущности остаются во внешнем
источнике: `get`, `values`, `entries`, `forEach` и предикаты читают их через текущий
resolver. Замена сущности в Map отражается в фильтре без перестроения; изменение
времени/связей требует нового индекса. Map сохраняется как источник, а не копируется.

`has` отвечает за привязанную ссылку. Неизвестный ключ `get` возвращает undefined;
удалённая из внешнего Map привязанная сущность вызывает RangeError при чтении.
Пользовательский get сам определяет обработку отсутствующих данных. Временной
запрос без предиката использует только метаданные и не читает сущности: он может
работать даже когда внешняя сущность уже недоступна.

## Точки и интервалы

Для работы с датами выбран date-fns. Пока Timeline принимает числовое время;
готовые Date и Interval преобразуйте в селекторе один раз при построении:

```ts
import { parseISO, addHours, getTime } from "date-fns";
import { timeline } from "ts-algo";

const start = parseISO("2026-10-05T10:00:00Z");
const end = addHours(start, 1);
const events = new Map([["meeting", { start, end }]]);
const history = timeline(events, {
  time: event => ({ start: getTime(event.start), end: getTime(event.end) }),
});
history.overlapping(getTime(start), getTime(end)); // ["meeting"]
```

date-fns устанавливается приложением отдельно. Прямой приём дат и типов
Interval запланирован в [архитектуре временного модуля](design.md#время-хронология-и-будущие-операции-интервалов).
Поддержку Date этот пример реализует через селектор, не через существующий
числовой тип EventTime.

- `between(a, b)` выбирает события, **начинающиеся** в `[a, b)`.
- `overlapping(a, b)` выбирает **пересекающие** `[a, b)`, включая начавшиеся раньше.
- Положительный интервал — `[start, end)`: конец ровно на a не пересекает окно.
- Число или `start === end` — точечное событие; оно включено при `a <= at < b`.
  `timeOf` возвращает для него число, для длительности — новый `{ start, end }`.
- Пустое окно возвращает пустой массив. Конечные number, общие единицы времени
  и `start <= end` обязательны; нарушение — RangeError. Даты и часовые пояса
  автоматически не преобразуются.
- Предикат внутри запроса вызывается только для временных кандидатов.
  `filter` проверяет все события и возвращает ссылки в хронологическом порядке.

Начала хранятся в отсортированном массиве; `between` использует два бинарных
поиска: O(log n + k), включая проверку k кандидатов. Только при наличии
длительностей создаются массив концов и max-end дерево в Float64Array. Оно
отбрасывает группы ранних событий, заканчивающиеся до окна. Это находит длинные
ранние интервалы, которые один поиск по start пропустил бы. Поиск пересечений
в худшем случае O(n); при большом числе пересечений требуется запись всех k
ссылок. Для одних точек этот дополнительный индекс не выделяется.

## Причинность

Можно передать `causes` и/или `effects`: направления дополняются автоматически,
повторные связи объединяются. Причина и следствие обязаны присутствовать в
составе; отсутствующая ссылка и цикл — RangeError. Несколько причин допустимы.
Ключи хронологии, в отличие от дерева, могут быть null/undefined.

Временной порядок не равен причинному: причина с более поздней временной меткой
допустима. `causalOrder` использует алгоритм Kahn с FIFO готовых узлов; начальные
узлы идут по времени, связи — по порядку объявления. Это детерминированный
топологический порядок, а не выбор самого раннего доступного узла на каждом шаге.
Без связей он совпадает с временным порядком.

`ancestors`/`descendants` возвращают уникальные ссылки обходом в ширину, ближайшие
сначала, без самого события. Прямые связи readonly; неизвестная ссылка — RangeError.
При обычной средней стоимости Map-операций построение O(n log n + r), память
O(n + e), где r — все переданные связи, e — уникальные. Причинный обход O(v + e)
для достижимой части; `causalOrder` копирует подготовленный массив за O(n).
